# Terjemahan (i18n) untuk modul

Panduan ini menjelaskan cara modul menulis, mengelola, dan menerjemahkan teks: tata letak katalog, sintaks pesan ICU, konvensi kunci, registri bahasa dan fallback, alur penerjemah, override istilah, dan kunci terketik. Keputusan dasarnya ada di PRD-000 FR-25 dan Q34 sampai Q35, dan spec rincinya di `.kiro/specs/i18n-platform/`.

Ringkasannya: satu katalog bersama untuk backend (Go) dan frontend (React), terpisah per namespace. Pesan memakai ICU MessageFormat. Backend menyajikan katalog lewat API per namespace, sehingga pemilik instalasi dapat mengganti istilah tanpa build ulang (override).

## Tata letak katalog dan namespace

Setiap namespace punya satu berkas JSON per bahasa.

| Namespace | Pemilik | Lokasi katalog |
| --- | --- | --- |
| slug modul, mis. `example` | modul itu sendiri | `modules/<name>/i18n/<locale>.json` |
| `ui` | komponen generik `@erpora/ui` | `packages/ui/i18n/<locale>.json` |
| `platform` | shell dan layanan platform | `internal/platform/i18n/catalog/<locale>.json` |

- Modul hanya membaca dan menulis namespace-nya sendiri, ditambah `ui` dan `platform`. Modul tidak boleh mengimpor `internal/platform/i18n` (aturan arsitektur `I1`) dan tidak boleh memuat literal kunci `"<ns>::…"` milik modul lain.
- Backend memakai `sdk/i18n` (`T`, `Lookup`, `WithLocale`, `WithScope`). Modul tidak memegang katalog mentah.
- Frontend memakai `useTranslation`, `msg()`, `crumb()`, dan `<Message>` dari `@erpora/platform-web` (lihat [`frontend.md`](frontend.md)).

## Format berkas: objek bersarang

Berkas katalog adalah objek JSON bersarang. Pesan adalah nilai string di daun.

```json
{
  "note": {
    "title": "Catatan",
    "count": "{count, plural, =0 {Belum ada catatan} other {# catatan}}",
    "status.draft": "Draf"
  },
  "fields": { "note": { "title": "Judul" } },
  "errors": { "not_found": "Catatan tidak ditemukan" }
}
```

Runtime dan pemeriksa meratakan pohon ini dengan menggabungkan segmen memakai `.`:

- `note.title`, `note.count`, `note.status.draft` (dari `"status.draft"`), `fields.note.title`, `errors.not_found`.
- Pencarian memakai peta hasil perataan. Akses dari kode selalu lewat kunci lengkap (`note.title`, atau `example::note.title` bila memakai namespace eksplisit).

Aturan segmen:

- Karakter yang diizinkan: `A-Z a-z 0-9 _ . -`.
- Segmen tidak kosong, tidak diawali atau diakhiri titik, tidak memuat `..`, dan tidak memuat `::` (pemisah namespace).
- Dua jalur yang menghasilkan kunci lengkap sama adalah galat (`flatten_collision`), dan laporannya menyebut kedua jalur. Contoh: `{"a.b": {"c": "x"}}` dan `{"a": {"b.c": "y"}}` keduanya menjadi `a.b.c`.
- Kunci ganda pada tingkat yang sama adalah galat (`duplicate_key`); pembaca JSON tidak membuang duplikat diam-diam.
- Struktur bersarang harus sama di setiap bahasa dalam satu namespace.

## Sintaks pesan ICU

Didukung:

- Argumen sederhana: `{name}`.
- `plural` dengan kategori CLDR `zero`, `one`, `two`, `few`, `many`, `other`, nilai eksplisit `=N`, dan `#` (nilai argumen).
- `select`: `{state, select, draft {Draf} other {Lainnya}}`.
- Tag rich bergaya ICU: `<b>…</b>`. Nama tag `[a-z][a-z0-9]*`. Komponen di sisi tampilan merendernya sebagai elemen React; `Format` teks polos melucutinya.
- Kutip ICU, mis. `'{'` untuk karakter kurung literal.

Ditolak (`unsupported_construct`): `selectordinal`, `number`, `date`, `time`, `offset`. Angka, tanggal, dan mata uang diformat di kode (`Intl` di frontend, `golang.org/x/text` di backend) lalu diteruskan sebagai argumen teks.

Ditolak lainnya:

- HTML dalam pesan (`html_not_allowed`). `<` hanya boleh sebagai tag rich bernama yang valid.
- Sintaks ICU tidak valid (`invalid_icu`).
- Pesan melebihi batas (`too_large`).

Batas bawaan (`sdk/i18n` `DefaultLimits`): panjang pesan 2000 karakter, kedalaman bersarang 8, opsi plural/select 20, argumen 32, kunci 5000 per namespace dan bahasa, berkas 1 MB, panjang kunci lengkap 200 karakter.

Aturan plural mengikuti CLDR dan sama di Go dan TypeScript. Fixture `sdk/i18n/testdata/conformance.json` dibaca oleh test Go dan `bun test` di `platform-web`. Di Go, kategori plural non-CLDR (mis. salah ketik) ditolak lebih ketat daripada FormatJS dan ditandai `goOnly` di fixture (Q37 butir 3).

Argumen yang tidak diberikan tidak membuat runtime crash: pesan ditampilkan dengan placeholder apa adanya, dan peringatan dicatat di development.

## Konvensi kunci

| Pola | Dipakai untuk |
| --- | --- |
| `fields.<resource>.<field>` | label field form dan nama field pada pesan validasi (teks yang sama di FE dan BE) |
| `errors.<code>` | pesan galat API; `code` tetap kontrak, hanya `message` yang diterjemahkan |
| `status.<kode>` | label status (mis. `status.draft`) |
| `nav.<area>.<item>` | label navigasi |
| `page.<halaman>.<bagian>` | teks halaman, mis. `page.notes.title` pada modul `example` |
| `actions.<aksi>` | label aksi halaman, mis. `actions.refresh` |

Konvensi di atas adalah pola yang dipakai katalog platform dan modul referensi. Kunci baru mengikuti pola yang paling dekat dengan fungsinya.

Pesan galat dari backend diterjemahkan otomatis: `sdk/httpx.WriteError` mencari `errors.<code>` pada namespace modul pemilik route, lalu `platform::errors.<code>`, dan memakai `message` pemanggil bila tidak ada. `code` dan `details` tidak berubah.

## Registri bahasa dan fallback

Registri ada di `internal/platform/i18n/locales.json` dan menjadi satu-satunya sumber daftar bahasa dan fallback (tidak ada pengaturan fallback per instalasi, Q35 butir 9). Isi saat ini:

```json
{
  "default": "id",
  "locales": [
    { "code": "id", "name": "Bahasa Indonesia" },
    { "code": "en", "name": "English", "fallback": "id" }
  ]
}
```

- `code` unik dengan pola `^[a-z]{2,3}(-[A-Z]{2})?$`.
- `fallback` harus menunjuk bahasa yang terdaftar. Rantai fallback tidak boleh bersiklus dan kedalamannya dibatasi (4). Bahasa default tidak punya `fallback`.
- `partial: true` menandai bahasa yang sengaja belum lengkap. Untuk bahasa itu, kunci yang hilang tidak dilaporkan dan teksnya jatuh ke fallback. Kunci berlebih dan argumen yang tidak cocok tetap dilaporkan. Saat ini tidak ada bahasa `partial` di registri.
- Modul hanya dapat menyediakan bahasa yang terdaftar.

Rantai pencarian untuk satu kunci, pada bahasa aktif `L`:

1. Override untuk `L` (lihat bagian override).
2. Katalog bawaan untuk `L`.
3. Bahasa fallback registri untuk `L`, dengan urutan yang sama (override dulu, lalu bawaan).
4. Bahasa default (`id`).
5. Bila tidak ada, hasilnya `namespace::kunci`, dan peringatan dicatat.

Bahasa aktif ditentukan dari pilihan pengguna (`user_preferences.locale` setelah PRD-001; sebelum itu preferensi UI di frontend), lalu `Accept-Language`, lalu bahasa default. Nilai yang tidak dikenal jatuh ke default tanpa error.

Manifest modul dapat mendeklarasikan `i18n: { "locales": [...], "defaultLocale": "..." }` (opsional, D-8). `module:check` memastikan setiap bahasa terdaftar, `defaultLocale` ada di `locales`, dan berkas `<locale>.json` ada. Modul yang membawa `CatalogSource` wajib punya bagian ini.

## Alur penerjemah

Semua perintah dijalankan dari root repo.

1. **Cek kelengkapan:** `task erpora -- i18n:status` menampilkan persentase kelengkapan per bahasa per namespace.
2. **Tambah bahasa baru:** `task erpora -- i18n:add <locale> [module...] [--name "<nama asli>"] [--fallback <kode>]`. Perintah ini membuat kerangka katalog dari bahasa default untuk modul yang dipilih. Struktur dan urutan kunci sama, dan nilainya diberi awalan penanda TODO (konstanta `TodoPrefix` di `internal/devtools/i18ntools/add.go`) sehingga mudah dicari. Bahasa yang belum ada didaftarkan ke registri.
3. **Terjemahkan:** isi nilai di `i18n/<locale>.json` lalu hapus penanda TODO.
4. **Periksa:** `task i18n:check` (mode biasa) atau `task i18n:check -- --strict` (peringatan menjadi galat). Tambahkan `--json` untuk keluaran mesin: berkas, bahasa, dan kunci lengkap per temuan.
5. **Bangkitkan tipe:** `task i18n:generate` menulis `keys.gen.ts`. `task i18n:generate -- --check` hanya memeriksa drift.

Pembagian temuan:

- **Galat (build gagal):** JSON tidak valid, ICU tidak valid, kunci ganda, tabrakan perataan, karakter segmen terlarang, kunci bernamespace pemilik lain, pesan berisi HTML, registri atau fallback tidak valid, dan modul mendeklarasikan bahasa yang tidak terdaftar.
- **Peringatan (build tetap lolos):** kunci hilang atau berlebih antar bahasa, dan argumen atau tipe argumen yang tidak sama dengan bahasa default. `--strict` mengubahnya menjadi galat.

Exit code `i18n:check`: 0 sukses, 2 galat validasi (kunci atau format), 3 prasyarat atau konfigurasi gagal (registri, manifest). Gate bawaan `task lint` dan `task web:check` memakai mode biasa.

## Kustomisasi istilah (override)

Pemilik instalasi dapat mengganti teks bawaan, mis. "Pelanggan" menjadi "Klien", tanpa mengubah kode atau membangun ulang. Override disimpan per tenant di tabel `i18n_overrides` dengan revisi per (namespace, bahasa) di `i18n_revisions`.

**Antarmuka utama (CLI produksi):**

```
erpora i18n override set <namespace> <locale> <key> <message>
erpora i18n override list [--namespace <ns>] [--locale <kode>] [--json]
erpora i18n override rm <namespace> <locale> <key> [--yes|-y]
```

`rm` meminta konfirmasi kecuali `--yes` dipakai. Exit code: 0 sukses atau tidak ada perubahan; 2 validasi; 3 prasyarat atau konfigurasi (termasuk guard lingkungan); 4 operasi gagal.

**API:**

| Endpoint | Permission | Keterangan |
| --- | --- | --- |
| `GET /api/platform/i18n/overrides` | `platform.i18n.read` | daftar override tenant; filter `namespace`, `locale`; paginasi halaman |
| `PUT /api/platform/i18n/overrides/{namespace}/{locale}/{key}` | `platform.i18n.manage` | simpan (upsert) dengan body `{ "message": "..." }`; mutasi wajib `Content-Type: application/json` |
| `DELETE /api/platform/i18n/overrides/{namespace}/{locale}/{key}` | `platform.i18n.manage` | hapus; teks kembali ke bawaan |

Mutasi API aktif hanya bila `ERP_ENV=development` atau `ERP_MODULES_ADMIN_API=true`. Di luar itu balasannya `404`. Ini pengamanan sementara sampai PRD-001 (Q35 butir D-5).

**Validasi** (`400 invalid_i18n_override`, dengan `error.details[].code`):

- `unknown_key`: kunci tidak ada di katalog bawaan bahasa default namespace itu. Override hanya untuk kunci yang sudah ada.
- `invalid_syntax`: sintaks ICU tidak valid.
- `param_mismatch`: argumen dan tipenya harus sama dengan pesan bawaan.
- `html_not_allowed`: tanpa HTML.
- `too_long`: batas 2000 karakter dan 8 KB body.

**Efek:** setiap perubahan menaikkan revisi namespace dan bahasa dalam transaksi yang sama. `ETag` katalog berubah, `bootstrap.i18n.revisions` berubah, dan frontend memuat ulang katalog tanpa reload halaman. Menyimpan nilai yang sama tidak menaikkan revisi. Setiap perubahan dicatat ke log terstruktur (`i18n_override_changed`) sampai audit writer PRD-001 tersedia.

Override tidak mengubah `code` pada galat API; hanya `message` yang berubah.

## Kunci terketik

- `i18n:generate` membangkitkan `keys.gen.ts` per paket dari katalog bahasa default. Berkas itu menambahkan augmentasi `I18nCatalogs` ke `@erpora/platform-web`. Jangan diedit.
- Kunci yang salah ketik, argumen yang hilang, atau tipe argumen yang salah menggagalkan `bun run typecheck`.
- Tipe argumen: argumen sederhana `string | number`, `plural` `number`, `select` literal gabungan, dan tag rich sebagai `RichTag`.
- `task web:check` menjalankan `i18n:generate --check`, sehingga berkas yang basi menggagalkan gate.

## Keamanan

- **Tanpa HTML.** Katalog dan override tidak boleh memuat HTML. Tag rich hanya tag bernama yang dirender komponen React. Tidak ada `innerHTML`; `dangerouslySetInnerHTML` dilarang oleh Biome.
- **Argumen dari pengguna** diperlakukan sebagai teks biasa dan di-escape oleh React. Backend mencetak `Format` teks polos ke email atau ekspor.
- **Tanpa data sensitif.** Katalog bersifat publik (tanpa login) di fase ini (Q35 butir D-4). Jangan memasukkan data pribadi, rahasia, atau data tenant ke pesan atau override.
- **Parameter tertutup.** `{locale}` dan `{namespace}` divalidasi terhadap registri dan daftar namespace aktif. Tidak ada akses path berkas dari input pengguna.
- **Tenant dari context.** Override selalu dibaca dan ditulis untuk tenant dari context, tidak dari parameter.
