# M2 — Module Registry: pembagian rencana

**Spec:** `docs/prd/PRD-000-inisialisasi-project.md` §11 (M2): FR-05, FR-06, FR-15, FR-18, FR-19, FR-20.1–20.2, FR-22, FR-23, FR-24.2, FR-16 (ADR-006/007), FR-07 guardrail 5, FR-14 workflow validasi tag rilis (Q23).

M2 mencakup empat subsistem yang masing-masing menghasilkan perangkat lunak yang dapat diuji sendiri. Karena itu M2 dipecah menjadi empat rencana yang dikerjakan **berurutan**. Exit gate M2 (PRD-000 §11) baru dinilai setelah M2d selesai.

| Rencana | Cakupan | Bergantung pada | Hasil yang dapat diuji |
| --- | --- | --- | --- |
| **M2a — Kontrak modul & registry** (`2026-10-22-m2a-module-contract-registry.md`) | FR-06 schema; FR-05 SDK + registry + rantai middleware + status guard; FR-18 compatibility & resolver; FR-15 backend `example` + `exampleaddon`; `erpora inspect routes/modules/permissions`; ADR-006 final | M1 | Binary memuat dua modul referensi, katalog divalidasi saat startup, route modul terpasang di `/api/{slug}` dengan guard (semua `available` → 404 sampai M2b) |
| **M2b — Lifecycle & manajemen** | FR-19 (tabel control, store, state machine, advisory lock, migrasi `goose_module_<slug>`, reconcile, runtime snapshot + `StateNotifier`, `required`); FR-20.1 CLI `erpora modules …`; FR-20.2 API `/api/platform/modules`; FR-22.4 command modul; bootstrap berisi modul; FR-07 guardrail 5; ADR-007 final | M2a | Semua AC FR-19 di integration test; kedua modul dapat dikelola penuh lewat CLI |
| **M2c — Primitif keamanan** | FR-24.2: `sdk/egress`, `sdk/httpx.DecodeJSON`, `Cache-Control: no-store` berbasis klasifikasi, `sdk/export`, arch test egress/decode | M2a | Test tabel SSRF, decode, ekspor lolos |
| **M2d — Developer tools & kontrak API** | FR-22 (make:*, db:*, module:check, doctor, penanda lingkungan, cek binary release); FR-23 (openapi per modul, Spectral, kesesuaian route ↔ kontrak, generate, oasdiff, klasifikasi di linter); tipe TS `packages/module-sdk` dibangkitkan dari `module.schema.json` (AC FR-06); FR-14 workflow tag rilis | M2a–M2c (template generator memakai primitif M2c; linter klasifikasi memakai FR-24.2) | `erpora make:module` menghasilkan modul yang lolos semua gate; exit gate M2 |

Alasan urutan M2c sebelum M2d: kode hasil `make:handler`/`make:module` harus langsung memakai `httpx.DecodeJSON` dan aturan klasifikasi, sehingga primitifnya wajib ada lebih dulu (PRD-000 FR-24: "setiap primitif keamanan sudah tersedia sebelum konsumen pertamanya ditulis").

Bagian frontend FR-15 (`module.ts`, route lazy, navigasi) dikerjakan di M3 bersama FR-08/FR-09, karena shell dan registry TS baru ada di sana.

Rencana M2b–M2d ditulis setelah rencana sebelumnya selesai dieksekusi, agar antarmuka yang dirujuk adalah antarmuka yang benar-benar ada.
